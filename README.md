## Problem
A potato cooperative in Musanze receives farm records in inconsistent spreadsheets. This prototype
(1) estimates harvest yield (regression), (2) flags farms at high production risk, meaning yield per hectare
below the median (classification), and (3) groups farms with similar conditions (clustering).
Training and CLI prediction work fully offline; a FastAPI service is provided for a future mobile app.

## Design notes
- One fixed split (`random_state=7935`, stratified on `high_risk`) is shared by all tasks.
- Imputation (median), scaling and one-hot encoding live inside scikit-learn Pipelines fitted on **training data only**; the same pipelines are used at inference.
- Models are selected by 5-fold cross-validation on the training set; the test set is used only for final reporting.
- Leakage guard: `yield_tons`, yield per hectare and `high_risk` can never be input features (`src/validation.py`).

## API examples
```bash
curl http://127.0.0.1:8000/health
curl http://127.0.0.1:8000/model-info
curl -X POST http://127.0.0.1:8000/predict -H "Content-Type: application/json" -d @samples/valid.json
```

Invalid input (wrong type, out of range, missing or unexpected field) returns HTTP 422 with a message. If models are missing, `/predict` returns 503.

## Dependencies
Only the libraries listed in `requirements.txt` (all required by the brief; `httpx` is needed by FastAPI's TestClient for API tests).

## Known limitations
Synthetic, independently generated features give weak natural clusters (silhouette about 0.14). Only five conditions are modelled.
Results do not transfer to real farms without real data and validation. Not for finance, insurance or public-service decisions.
A human (agronomist or field officer) must review every output.
